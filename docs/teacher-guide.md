# Teacher's Guide to Requesting Changes

This guide explains how teachers can easily request changes to the Mergington High School Management System without needing to modify code directly.

## How to Request Changes

Instead of editing code, you can now create detailed issue requests using our templates. Simply follow these steps:

### Step 1: Create a New Issue

1. Go to the [Issues tab](../../issues) in this repository
2. Click the green **"New Issue"** button
3. You'll see a list of templates to choose from

### Step 2: Choose the Right Template

We have created several templates for common tasks:

#### 🎯 **Add New Activity**
Use this when you want to add a completely new extracurricular activity to the system.

**Example scenarios:**
- Adding a new "Coding Club" that meets on Tuesdays
- Adding a "Science Fair Prep" activity
- Adding a weekend workshop

**What you'll provide:**
- Activity name
- Description
- Schedule (days and times)
- Maximum number of participants

---

#### ✏️ **Modify Existing Activity**
Use this when you need to change details of an activity that already exists.

**Example scenarios:**
- Chess Club needs to change from Monday/Friday to Tuesday/Thursday
- Programming Class needs to increase participant limit from 20 to 25
- Drama Club description needs to be updated

**What you'll provide:**
- Which activity to modify
- What needs to change (schedule, description, participant limit, etc.)
- The new values
- Reason for the change

---

#### 🐛 **Bug Report**
Use this when something isn't working correctly.

**Example scenarios:**
- Students can't sign up for an activity
- Wrong schedule is displayed
- Participant count is incorrect
- Login isn't working

**What you'll provide:**
- Clear description of the problem
- Steps to reproduce the issue
- What should happen vs. what actually happens
- Who is affected (students, teachers, or both)

---

#### 🎨 **UI/UX Improvement**
Use this when you want to improve how the website looks or how users interact with it.

**Example scenarios:**
- Activity cards are hard to read
- Colors need to be more school-themed
- Search function could be more visible
- Mobile experience needs improvement

**What you'll provide:**
- What part of the website to improve
- Current experience vs. desired improvement
- Who would benefit from this change

---

#### ✨ **New Feature Request**
Use this when you want to add a completely new capability to the system.

**Example scenarios:**
- Add a calendar view of all activities
- Add email notifications for students
- Add activity categories or tags
- Add a way for students to see their signed-up activities

**What you'll provide:**
- Feature name and description
- Problem this solves
- How it should work
- Who would use this feature

---

#### 📚 **Documentation Update**
Use this when documentation needs to be corrected or improved.

**Example scenarios:**
- Setup instructions are outdated
- Missing explanation for a feature
- Developer guide needs corrections
- README needs updates

**What you'll provide:**
- What documentation is wrong or missing
- What it should say instead
- Reason for the update

---

### Step 3: Fill Out the Template

Each template has specific fields that guide you through providing all the necessary information. 

**Required fields** are marked and must be filled out. These ensure that GitHub Copilot or developers have enough context to understand and implement your request.

**Optional fields** can provide additional helpful context.

### Step 4: Submit and Track

1. Click **"Submit new issue"** when you're done
2. Your issue will be created with a unique number
3. You can track its progress in the Issues tab
4. You'll receive notifications when there are updates

## Why Use Templates?

✅ **No coding required** - Just fill out forms with plain language

✅ **Nothing gets missed** - Templates ensure you provide all necessary information

✅ **Faster implementation** - Complete information means GitHub Copilot can start work immediately

✅ **Better results** - Clear requirements lead to better solutions

✅ **Easy tracking** - See the status of all your requests in one place

## Tips for Writing Good Issue Requests

### Be Specific
- ❌ "Fix the schedule"
- ✅ "Change Chess Club schedule from Monday/Friday 3:15-4:45 PM to Tuesday/Thursday 3:30-5:00 PM"

### Explain Why
- ❌ "We need a new activity"
- ✅ "We need a Robotics Workshop because 15 students have requested it and we secured funding for equipment"

### Include Examples
- ❌ "Make it look better"
- ✅ "Make activity cards easier to read by using larger fonts and more spacing, like the cards on example.com"

### Describe Expected Results
- ❌ "It's broken"
- ✅ "When students click 'Sign Up', they should be added to the activity, but instead they get an error message"

## Getting Help

If you're unsure which template to use or need help:

1. Read the template descriptions carefully
2. Choose the one that best matches your need
3. If still unsure, use **Feature Request** for new capabilities or **Bug Report** for things that aren't working
4. Add any questions in the "Additional Context" section of the template

## Questions?

For technical setup or development questions, see the [Development Guide](how-to-develop.md).

For questions about using these templates, reach out to your system administrator or technical contact.

---

**Remember:** You don't need to know how to code to request changes. Just describe what you need in plain language using these templates, and the system will guide you through providing all the necessary details! 🎓
